# 0012. The environment has to be reproducible, so nothing is protected from destruction

Accepted, 2026-08-07. Supersedes [0008](0008-prevent-destroy-on-stateful-resources.md).

## Context

[0008](0008-prevent-destroy-on-stateful-resources.md) put `prevent_destroy` on the seven resources
carrying state, on tflint's reading, so that no plan could ever propose to drop them.

It also wrote down what that costs: `prevent_destroy` takes a literal, no variable softens it, and
tearing the environment down starts by removing the blocks in a commit of its own.

That cost turns out to be the wrong one to pay here. This is a non-production environment whose
whole claim is that it can be rebuilt from this repository. A teardown that first needs a code
change, a review and a merge is not a teardown anyone will run, so the claim goes untested and the
first real rebuild happens on the day something is already broken.

The database content argues the same way. Fifteen Flyway migrations, twelve of them inserting,
rebuild every module, every mock exam and every certification. What a destroyed database loses is
the quiz sessions played against it, which in this environment is test data.

## Decision

The seven `prevent_destroy` blocks are removed. `terraform destroy` runs to completion, and
[the destroy workflow](../../.github/workflows/cd-destroy.yml) is the way it is reached.

## Consequences

The guard 0008 wanted is gone with it, and it was a real guard: a changed argument silently forcing
a replacement is how data disappears without anyone deciding to delete it. What remains against it
is the plan, printed on every pull request, and a reader who looks at it.

Destroying is now three deliberate acts rather than four: typing the resource group name into the
dispatch form, approving the `nonprod` environment, and living with the result. The state stays
protected by its own lock and its own storage account, which this configuration does not manage.

Two things still stand outside the cycle, and cannot be brought in. The storage account holding the
state cannot be created by the Terraform that writes its state into it, and the app registration
GitHub signs in as cannot be created by the pipeline that signs in with it.
[`scripts/bootstrap-oidc.sh`](../../scripts/bootstrap-oidc.sh) creates both, once.

The Static Web App hostname is generated by Azure. A rebuilt environment answers on a different
one, which the pipelines survive since they resolve it by tag, and which the README and the diagram
do not.
